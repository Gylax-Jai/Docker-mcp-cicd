1. WHAT IS DOCKER & WHY DO WE NEED IT?
========================================================================================================

Docker is an open-source containerization tool that packages an application along with all of its 
dependencies, libraries, configuration files, and runtime into a single standalone unit called a CONTAINER.


--------------------------------------------------------------------------------------------------------
★ THE PROBLEM: "IT WORKS ON MY MACHINE!"
--------------------------------------------------------------------------------------------------------

  WITHOUT DOCKER:
  • Developer 1 runs Node v18 on macOS.
  • Developer 2 runs Node v20 on Windows.
  • Production server runs Node v16 on Ubuntu.
  -> Code crashes because of mismatched package versions, missing libraries, or OS path differences!

  WITH DOCKER:
  • Everyone runs the exact same isolated container image.
  • If it runs on your computer inside Docker, it is 100% GUARANTEED to run identically on any server.


--------------------------------------------------------------------------------------------------------
★ HOW DOCKER EMPOWERS A TEAM
--------------------------------------------------------------------------------------------------------

  1. New teammate joins the project.
  2. They clone the code from GitHub.
  3. They run ONE command:  docker compose up
  4. Docker automatically sets up:
     - Frontend (React)
     - Backend (Node.js/Express)
     - Database (MongoDB / PostgreSQL / Redis)
  -> Zero manual installation required! Ready to code in seconds.

2. ARCHITECTURE: VIRTUAL MACHINES (VM) vs DOCKER CONTAINERS
========================================================================================================

--------------------------------------------------------------------------------------------------------
[DIAGRAM 1: ARCHITECTURE COMPARISON]
--------------------------------------------------------------------------------------------------------

      VIRTUAL MACHINE (Heavy & Slow)                     DOCKER CONTAINER (Lightweight & Fast)
  ┌─────────────────────────────────────────┐         ┌─────────────────────────────────────────┐
  │   App 1          │        App 2         │         │   App 1          │        App 2         │
  │   (Bin / Libs)   │        (Bin / Libs)  │         │   (Bin / Libs)   │        (Bin / Libs)  │
  ├──────────────────┼──────────────────────┤         ├──────────────────┴──────────────────────┤
  │   Guest OS 1     │        Guest OS 2    │         │              Docker Engine              │
  │   (Full Ubuntu)  │        (Full Windows)│         │     (Shares Single Host OS Kernel)      │
  ├──────────────────┴──────────────────────┤         ├─────────────────────────────────────────┤
  │               Hypervisor                │         │                 Host OS                 │
  ├─────────────────────────────────────────┤         ├─────────────────────────────────────────┤
  │             Physical Server             │         │             Physical Server             │
  │        (CPU / RAM / Hard Disk)          │         │        (CPU / RAM / Hard Disk)          │
  └─────────────────────────────────────────┘         └─────────────────────────────────────────┘

  KEY DIFFERENCES:
  • Size      : VMs are 5GB to 20GB each              • Size      : Containers are 50MB to 500MB
  • Boot Time : Takes 1 to 5 minutes to start         • Boot Time : Starts in milliseconds
  • Memory    : Allocates fixed RAM permanently       • Memory    : Uses only what is needed dynamically

3. ESSENTIAL VOCABULARY & CORE CONCEPTS
========================================================================================================

  1. DOCKER IMAGE
     • A read-only template / blueprint / snapshot containing the code and software.
     • Analogy: A recipe for baking a cake, or an architectural floor plan.
     • Examples: mongo:latest, node:20-alpine, nginx:alpine.

  2. DOCKER CONTAINER
     • A live, running instance created from an image.
     • Analogy: The actual baked cake, or the physical house built from the plan.
     • You can run multiple separate containers from a single image.

  3. DOCKERFILE
     • A text document containing step-by-step instructions to build your own custom image.

  4. DOCKER COMPOSE (docker-compose.yml)
     • A YAML configuration file used to define and run multi-container applications together.

  5. DOCKER HUB
     • A public cloud registry / app store where official pre-built images are hosted.

  6. DOCKER VOLUME (-v)
     • Persistent storage on your host computer's hard disk so data survives container deletion.

  7. DOCKER NETWORK (--network)
     • A virtual communication highway that allows containers to talk to each other by name.

6. VOLUMES: PERSISTING DATA ACROSS CONTAINER LIFECYCLES
========================================================================================================

--------------------------------------------------------------------------------------------------------
[DIAGRAM 4: WITHOUT VOLUME vs WITH VOLUME]
--------------------------------------------------------------------------------------------------------

  CASE A: WITHOUT VOLUME (-v omitted)

      ┌─────────────────────────────────┐
      │         mongo container         │
      │   Internal Storage: /data/db    │  <--- Data is trapped inside container
      └─────────────────────────────────┘
                      │
                      │  docker rm mongo  (Container is deleted)
                      ▼
         💥 [ ALL DATA IS PERMANENTLY DESTROYED ] ❌


  CASE B: WITH VOLUME (-v favorites-mongo-data:/data/db)

      ┌─────────────────────────────────┐
      │         mongo container         │
      │   Internal Path: /data/db       │
      └────────────────┬────────────────┘
                       │
                       │  Volume mapping links container to host
                       ▼
      ┌─────────────────────────────────┐
      │   Physical Host Storage (PC)    │
      │   📁 favorites-mongo-data       │  <--- Data actually lives on your hard drive!
      └─────────────────────────────────┘
                      │
                      │  docker rm mongo  (Container is deleted)
                      ▼
         ✅ [ DATA IS 100% SAFE ON YOUR HARD DRIVE ]
         (When you launch a new Mongo container with the same volume, all past data reappears!)

7. WHY NGINX IS USED FOR REACT (NOT A "REACT IMAGE")
========================================================================================================

  • React is purely a client-side JavaScript library.
  • In development: "npm run dev" uses Vite's Node-based development server.
  • In production: "npm run build" compiles JSX/TSX into raw static files (HTML, CSS, JS) inside /dist.
  • We use Nginx because it is an ultra-fast, lightweight web server specifically designed 
    to serve static files and proxy API requests.

--------------------------------------------------------------------------------------------------------
[DIAGRAM 5: MULTI-STAGE DOCKER BUILD FOR REACT]
--------------------------------------------------------------------------------------------------------

    STAGE 1: BUILD STAGE (node:20-alpine)
    ┌───────────────────────────────────────────┐
    │  1. Copy source code & package.json       │
    │  2. Run 'npm install'                     │
    │  3. Run 'npm run build'                   │
    │  -> Outputs production bundle to /dist    │
    └─────────────────────┬─────────────────────┘
                          │
                          │ Copies ONLY the compiled /dist folder
                          ▼
    STAGE 2: PRODUCTION STAGE (nginx:alpine)
    ┌───────────────────────────────────────────┐
    │  1. Put HTML/CSS/JS in /usr/share/nginx   │
    │  2. Start Nginx web server on port 3000   │
    │  -> Discards heavy node_modules!          │
    │  -> Result: Tiny image (~25MB total!)     │
    └───────────────────────────────────────────┘

8. ONE MONGODB CONTAINER FOR MULTIPLE PROJECTS
========================================================================================================

You do NOT need to launch multiple Mongo containers for different learning projects.
A single Mongo container can host dozens of isolated databases simultaneously.

  Connection String Structure:
  mongodb://mongo:27017/<DATABASE_NAME>

  Examples:
  • Project 1: mongodb://mongo:27017/favorites_db
  • Project 2: mongodb://mongo:27017/ecommerce_db
  • Project 3: mongodb://mongo:27017/blog_db

  MongoDB automatically creates and separates each database internally.

9. COMPLETE STEP-BY-STEP MANUAL WORKFLOW
========================================================================================================

STEP 1: INSTALL DOCKER DESKTOP & WSL2
  • Install Docker Desktop for Windows (AMD64 for Intel/AMD processors).
  • If prompted, install WSL2 in PowerShell:
      wsl --install
  • Keep Docker Desktop running in the background.

STEP 2: VERIFY INSTALLATION
  docker --version
  docker run hello-world

STEP 3: CREATE DOCKER NETWORK
  docker network create favorites-network
  (Enables all containers on this network to resolve each other by container name).

STEP 4: RUN MONGODB CONTAINER
  docker run -d \
    --name mongo \
    --network favorites-network \
    -p 27017:27017 \
    -v favorites-mongo-data:/data/db \
    mongo:latest

  FLAG BREAKDOWN:
  • -d                            : Detached mode (runs container in background)
  • --name mongo                  : Custom container name (used by backend to connect)
  • --network favorites-network   : Attaches container to our shared network
  • -p 27017:27017                : Port mapping (Host Port : Container Port)
  • -v favorites-mongo-data:/data/db : Mounts persistent storage volume
  • mongo:latest                  : The image name to pull and run

STEP 5: BUILD & RUN BACKEND CONTAINER
  cd backend
  docker build -t favorites-backend .
  docker run -d --name backend --network favorites-network -p 5000:5000 favorites-backend

  FLAG BREAKDOWN:
  • -t favorites-backend          : Tag / name for the new custom image
  • .                             : Build context (look for Dockerfile in current folder)

STEP 6: BUILD & RUN FRONTEND CONTAINER
  cd ../frontend
  docker build -t favorites-frontend .
  docker run -d --name frontend --network favorites-network -p 3000:3000 favorites-frontend

STEP 7: VERIFY AND ACCESS
  docker ps
  Open browser at: http://localhost:3000

10. DOCKER COMPOSE: ORCHESTRATING EVERYTHING IN ONE FILE
========================================================================================================

Docker Compose replaces all manual build, run, network, and volume commands with a single YAML file.

--------------------------------------------------------------------------------------------------------
[DIAGRAM 6: DOCKER COMPOSE STRUCTURE]
--------------------------------------------------------------------------------------------------------

  ┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
  │                                       docker-compose.yml                                         │
  │                                                                                                  │
  │   services:                                                                                      │
  │     mongo:                                                                                       │
  │       image: mongo:latest                                                                        │
  │       ports: ["27017:27017"]                                                                     │
  │       volumes: [favorites-mongo-data:/data/db]                                                   │
  │                                                                                                  │
  │     backend:                                                                                     │
  │       build: ./backend                                                                           │
  │       ports: ["5000:5000"]                                                                       │
  │       depends_on: [mongo]          <--- Waits for Mongo to start first                           │
  │                                                                                                  │
  │     frontend:                                                                                    │
  │       build: ./frontend                                                                          │
  │       ports: ["3000:3000"]                                                                       │
  │       depends_on: [backend]        <--- Waits for Backend to start first                         │
  │                                                                                                  │
  │   volumes:                                                                                       │
  │     favorites-mongo-data:                                                                        │
  │       external: true               <--- Uses existing volume to preserve data                    │
  └──────────────────────────────────────────────────────────────────────────────────────────────────┘

★ COMPOSE COMMANDS SUMMARY:
  • docker compose up --build  : Builds images, creates network, mounts volumes, and starts all services
  • docker compose up -d       : Starts all containers detached in the background
  • docker compose down        : Stops and deletes containers + network (Volumes & Images stay safe!)
  • docker compose down -v     : Stops containers AND deletes all volumes (Erases database data!)
  • docker compose logs -f     : Streams live console logs from all running containers

11. CHEAT SHEET: ALL ESSENTIAL DOCKER COMMANDS
========================================================================================================

── 1. WORKING WITH IMAGES ─────────────────────────────────────────────────────────────────────────────
  docker images                           List all local images stored on your PC
  docker pull <image_name>                Download an image from Docker Hub (e.g. docker pull redis)
  docker build -t <image_name> .          Build an image from a Dockerfile in the current directory
  docker rmi <image_name>                 Delete an image from local storage

── 2. WORKING WITH CONTAINERS ─────────────────────────────────────────────────────────────────────────
  docker run [flags] <image_name>         Create and start a new container
  docker ps                               List only currently running containers
  docker ps -a                            List all containers (running + stopped + exited)
  docker stop <container_name>            Stop a running container safely
  docker start <container_name>           Restart a previously stopped container (no flags needed!)
  docker rm <container_name>              Delete a stopped container
  docker rm -f <container_name>           Force delete a container even if it is currently running
  docker logs <container_name>            View terminal output logs of a container
  docker exec -it <container_name> sh     Open an interactive terminal shell inside a container

── 3. VOLUMES & NETWORKS ──────────────────────────────────────────────────────────────────────────────
  docker volume ls                        List all existing storage volumes
  docker volume rm <volume_name>          Delete a specific volume
  docker network ls                       List all virtual networks
  docker network create <network_name>    Create a new private network
  docker network rm <network_name>        Delete a network

── 4. DOCKER COMPOSE ──────────────────────────────────────────────────────────────────────────────────
  docker compose up --build               Build images and start all services
  docker compose up -d                    Start all services in the background
  docker compose down                     Stop and delete all compose containers & networks
  docker compose logs                     View logs across all compose services

── 5. SYSTEM MAINTENANCE ──────────────────────────────────────────────────────────────────────────────
  docker system prune                     Remove all stopped containers, unused networks, and build cache

13. MODEL CONTEXT PROTOCOL (MCP) INTEGRATION
========================================================================================================

Model Context Protocol (MCP) is an open standard protocol (JSON-RPC) that allows AI Assistants 
(like Claude Desktop, Antigravity, or Cursor) to securely connect to external tools and databases.

--------------------------------------------------------------------------------------------------------

                                      │
                                      │ JSON-RPC Protocol (MCP over STDIO)
                                      ▼
